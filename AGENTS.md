## Project

- **Name:** anime-analytics
- **One-line purpose:** End-to-end anime analytics platform with static/incremental ingestion, dbt star-schema warehouse, Power BI dashboards, and hybrid recommendation engine.
- **Stack:** Python 3.11, PySpark 3.5, PostgreSQL 16, MinIO, dbt-core 1.8+, Apache Airflow 2.9+, FastAPI, Streamlit, Power BI Desktop, MLflow
- **Package manager / runtime:** `uv` / `pip` (Python 3.11), Docker Compose

## Commands

- Install: `pip install -r requirements.txt` / `uv sync`
- Dev server (API): `uvicorn api.main:app --reload`
- Dev server (UI): `streamlit run ui/streamlit_app.py`
- Docker stack: `docker compose up -d`
- Test: `pytest`
- Lint / format: `ruff check .`
- dbt: `cd warehouse && dbt run && dbt test`
- Tickets Index: `cd tickets && bash _generate_index.sh`

## Conventions

- Code style: Standard Python (PEP 8, type hints, ruff linting)
- File/folder structure: Per TRD §3 architecture blueprint
- Naming conventions: snake_case for tables/files, PascalCase for classes
- SQL conventions: Uppercase keywords, dbt modular models (staging/intermediate/marts)

## Tickets

Work is tracked as one file per ticket in `tickets/*.md` — not GitHub Issues, not a flat
TICKETS.md. See `tickets/README.md` (regenerated by `tickets/_generate_index.sh`) for the
current open/blocked/in-progress list. Each ticket's frontmatter carries status,
assigned-role, and depends-on.
